# เพื่อนรัก · PeunRak

คุยได้ก่อนจะบอกใคร แล้วพาไปหาคนที่ช่วยได้จริง — **สะพาน ไม่ใช่ปลายทาง**
ระบบดูแลสุขภาพจิตนักเรียน — MVP สำหรับ Mahidol Public Health Hackathon 2026

PeunRak คือ "ประตูบานเดียว" ที่นักเรียนคุยได้ก่อนจะบอกใคร ระบบคัดกรองด้วยแบบประเมินมาตรฐาน
แยกว่าความทุกข์มาจากปัจจัยเสี่ยงด้านไหน แล้วพาไปถึงคนที่ช่วยได้จริง โดยไม่มีบทสนทนาถูกเก็บแม้แต่คำเดียว

1. **ความเป็นส่วนตัวระดับโครงสร้าง** — schema ไม่มีคอลัมน์บทสนทนา AI ตัวที่สองส่งออกแค่ id / คะแนน / ความมั่นใจ
2. **นักเรียนเลือกระดับการเปิดเผยเอง** (L0–L3) และ server เก็บข้อมูลเท่าที่ระดับนั้นอนุญาต
3. **ปิดวงจรส่งต่อ** จนเด็กไปถึงคนที่ช่วยได้จริง และวัดได้

ระบบนี้เป็นการดูแลระยะแรก + คัดกรอง + ส่งต่อ **ไม่ใช่การรักษา และไม่วินิจฉัย**

```bash
npm install && npm run dev     # เปิดแอป
npm test                       # unit test 34 ข้อ (ต้องใช้ Node 22.18 ขึ้นไป)
npm run redteam                # บทสนทนาจำลอง 30 เคส + ตรวจโครงสร้าง 9 ข้อ
```

## เลือกโมเดล

ระบบใช้ **Claude (Anthropic)** เมื่อมีคีย์ และตกไป **โหมดสาธิต** เมื่อไม่มี

```bash
cp .env.example .env.local
```

| ใส่คีย์ตัวไหน | ใช้อะไร | คีย์เอาจากไหน |
|---|---|---|
| `ANTHROPIC_API_KEY` | `claude-sonnet-5-5` (แชท) + `claude-haiku-5-5` (ประเมินเสี่ยง) | [console.anthropic.com](https://console.anthropic.com) |
| ไม่ใส่เลย | โหมดสาธิต (`lib/fallback.ts`) | — |

ต้อง **restart dev server** หลังใส่คีย์ ถ้าจะเปลี่ยนรุ่น แก้ค่าคงที่ `CLAUDE_CHAT` / `CLAUDE_FAST` ใน `lib/llm.ts` (แต่ละรุ่นรับพารามิเตอร์ไม่เหมือนกัน อ่านเอกสารของรุ่นนั้นก่อน)

> **เดิมแอปนี้ใช้ Gemini เป็นตัวหลัก เปลี่ยนเป็น Claude เมื่อ 26 พ.ย. 2569** เพราะเงื่อนไขของ Google ห้ามใช้ Generative AI ในบริการที่ผู้อายุต่ำกว่า 18 ปีเข้าถึง —
> ดูเหตุผลและเงื่อนไขของ Anthropic ที่หัวข้อ [ผู้ให้บริการ AI เก็บอะไร](#ผู้ให้บริการ-ai-เก็บอะไร)

โค้ดที่เรียกผู้ให้บริการอยู่ที่ [`lib/llm.ts`](lib/llm.ts) ไฟล์เดียว — ส่วนอื่นของแอปไม่รู้ว่าใช้เจ้าไหน ถ้าโมเดลปฏิเสธคำขอหรือเรียกไม่สำเร็จ แชทจะตอบด้วยกฎตายตัวใน `lib/fallback.ts` แทน นักเรียนจะไม่เจอหน้าจอว่าง

โหมดสาธิตตอบตามหัวข้อที่เด็กพูดจริงและมีเส้นทางฉุกเฉินครบ มีป้าย "โหมดสาธิต" บอกบนหน้าแชท
แต่ไม่ฉลาดเท่าโมเดลจริง — มีไว้กันเดโมพัง ไม่ใช่ตัวจริง (จับจากรายการคำ สำนวนที่ไม่อยู่ในรายการจะหลุด)

| ตัวแปรเสริม | ใช้ทำอะไร |
|---|---|
| `FORCE_DEMO=1` | บังคับโหมดสาธิตแม้จะมีคีย์ — ใช้วันเดโมถ้าเน็ตหรือ API ไม่นิ่ง |
| `NEXT_PUBLIC_BREAK_MINUTES` | คุยต่อเนื่องเกินกี่นาทีจึงเตือนพัก (ค่าเริ่มต้น 30) ตั้งให้สั้นลงได้ตอนสาธิต |

## เข้าใช้งาน

หน้าแรกคือ login ด้วยอีเมลโรงเรียน เลือกบทบาทได้ 3 แบบ (เดโมกดเข้าได้เลย ยังไม่เช็ครหัส)

| บทบาท | เข้าไปเจอ |
|---|---|
| นักเรียน | อ่านข้อตกลง 3 ข้อ → `/chat` แล้วมีแท็บล่าง: คุย · ไปหาคน · แบบทดสอบ · โปรไฟล์ |
| ครูแนะแนว | `/counselor` คิวตามขั้นการดูแล + คำขอติดต่อกลับ + funnel การส่งต่อ → `/admin` ตัวชี้วัด |
| ผู้เชี่ยวชาญ | `/specialist` เคสที่ถูกส่งต่อออกนอกโรงเรียน + บันทึกวันนัด/การเข้าพบ |

### ลำดับสาธิตที่เห็นครบทุกส่วน

1. นักเรียน: ติ๊กข้อตกลง → คุย 6–7 ข้อความ (เช่น เบื่อ เศร้า นอนไม่หลับ เหนื่อย กินไม่ลง รู้สึกล้มเหลว ไม่มีสมาธิ เครียดเรื่องสอบ)
   → การ์ดช่องทางช่วยเหลือขึ้นเอง และระบบชวนไปหาคนเมื่อระดับขยับ
2. พิมพ์ "มีคนโทรมาบอกว่าบัญชีผมพัวพันฟอกเงิน ห้ามบอกพ่อแม่" → การ์ด 1441
3. กด **ดูสรุป** → ระบบถามก่อนว่าจะช่วยตรวจความแม่นไหม (validation แบบปิดตา) → สรุปจากการคุยจริง + ขั้นต่อไป
4. เลือกระดับการเปิดเผย → เปิดแท็บครูแนะแนว: แท็กหมวดเรื่องขึ้นเฉพาะเมื่อเปิด L1 ขึ้นไป
5. กด **พาไปหาคน** → ครูแนะแนว → ครูเห็นคำขอ กดรับเรื่อง ส่งต่อ ใส่วันนัด
6. นักเรียนเปิดแท็บ **ไปหาคน**: เห็นวันนัด เลือกผู้ร่วมทาง ได้รับเตือน และเช็กอินหลังนัด
7. ครูเปิด **เอกสารส่งต่อ** ของเคส และ **ตัวชี้วัด**

## AI สองตัว ทำงานคนละหน้าที่

```
ตัวที่ 1  สนทนา         /api/chat    — คุยกับนักเรียน
ตัวที่ 2  ประเมินเสี่ยง   /api/risk    — ทำงานเบื้องหลัง สกัดว่าข้อไหนของแบบประเมินมีหลักฐาน + หมวดเรื่อง
ตัวที่ 3  คำนวณคะแนน    lib/instruments.ts  — โค้ดล้วน ไม่มี AI
```

**AI ไม่ได้ให้คะแนน** — AI ตัวที่สองบอกแค่ว่า "ข้อไหนมีหลักฐาน มั่นใจแค่ไหน" แล้วโค้ดคำนวณตามเกณฑ์ 9Q / GAD-7 / 8Q
ข้อที่มั่นใจไม่ถึงเกณฑ์ไม่ถูกนับ และถ้าหลักฐานยังน้อย ระบบขึ้นว่า "ข้อมูลยังไม่พอ" แทนที่จะบอกว่าเสี่ยงต่ำ

เส้นทางของข้อความหนึ่งข้อความ

```
นักเรียนพิมพ์
  → เครื่องนักเรียนตัดชื่อ/เบอร์ที่กรอกไว้ในโปรไฟล์ออก          (maskKnown)
  → server ตัดเบอร์ เลขบัตร อีเมล โซเชียล โรงเรียน/ห้อง ชื่อ ออกอีกชั้น   (redact ที่ lib/llm.ts จุดเดียว)
  → ผู้ให้บริการ AI ประมวลผล แล้วตอบกลับ
  → server เก็บเฉพาะตัวเลข: คะแนน ระดับ หมวดเรื่อง (ตามระดับที่นักเรียนเลือก)
ข้อความไม่ถูกเขียนลงที่เก็บของระบบในขั้นไหนเลย
```

ทดสอบได้เอง: เปิด `/chat` พิมพ์อะไรก็ได้ แล้วเปิด `/counselor` อีกแท็บ — คะแนนขยับใน 3 วินาที

## ความเป็นส่วนตัว

### บันไดการเปิดเผย (นักเรียนเลือกเอง)

| ระดับ | ครูเห็นอะไร | server เก็บอะไร |
|---|---|---|
| **L0** เก็บไว้ดูเอง (ค่าเริ่มต้น) | ระดับความเสี่ยงแบบนิรนาม | คะแนนเท่านั้น — ไม่เก็บหมวดเรื่อง ไม่เก็บชื่อ |
| **L1** ให้ครูรู้แบบไม่ระบุตัวตน | + หมวดเรื่อง | + หมวดเรื่อง (id + ความมั่นใจ) |
| **L2** เปิดชื่อให้ครู | + ชื่อและห้อง | + ชื่อและห้อง |
| **L3** ยินยอมให้ส่งต่อผู้เชี่ยวชาญ | + คะแนนรายข้อในเอกสารส่งต่อ | + คะแนนรายข้อ (id ข้อ + คะแนน + ความมั่นใจ) |

กติกานี้บังคับที่ `disclose()` ใน [`lib/store.ts`](lib/store.ts) จุดเดียว และกรองซ้ำที่ API (`forStaff`)
— เปิด `/api/monitor` ตรง ๆ ก็ไม่เห็นเกินระดับที่เด็กเลือก ลดระดับเมื่อไหร่ ข้อมูลของระดับที่สูงกว่าถูกลบออกทันที ไม่ใช่แค่ซ่อน
เลือกได้ที่หน้าสรุป (`/result`) หน้าไปหาคน (`/journey`) และสวิตช์ในโปรไฟล์

ชื่อเพื่อนหรือครูที่พิมพ์ติดกับประโยคโดยไม่มีคำนำ (เช่น "ครูสมศรีด่าเรา") ยังหลุดได้ — บันทึกไว้เป็นเทสต์ใน
[`scripts/unit/redact.test.mjs`](scripts/unit/redact.test.mjs) และข้อตกลงหน้าแรกบอกนักเรียนตรง ๆ ว่าไม่ควรพิมพ์ข้อมูลพวกนี้

### ผู้ให้บริการ AI เก็บอะไร

ตรวจจากหน้าเงื่อนไขของผู้ให้บริการเมื่อ 26 พ.ย. 2569 — **[ต้องยืนยัน] เปิดหน้าเงื่อนไขฉบับปัจจุบันอีกครั้งก่อนใช้จริงและก่อนอ้างในเอกสาร**

| ผู้ให้บริการ | สิ่งที่พบ | ผลต่อโครงการ |
|---|---|---|
| **Anthropic API (ที่แอปใช้อยู่)** | ลบ input/output ภายใน 30 วันโดยปริยาย ไม่ใช้ฝึกโมเดลเว้นแต่ได้รับอนุญาต ขอ zero data retention ได้เป็นรายองค์กร Usage Policy (มีผล 12 พ.ย. 2026) อนุญาตผลิตภัณฑ์ที่ให้บริการผู้เยาว์เมื่อทำตามแนวทางเพิ่มเติม และจัดการ “assessing, diagnosing, or treating a mental health condition” เป็น high-risk: ต้องมีผู้มีคุณวุฒิทบทวนก่อนส่งถึงผู้ใช้ และต้องบอกว่าใช้ AI | ใช้ในรอบนำร่องได้ **เมื่อ** ทำตามแนวทางสำหรับผู้เยาว์ และให้ครูแนะแนวหรือนักจิตวิทยาทบทวนผลก่อนแสดงต่อนักเรียน — ต้นแบบปัจจุบันยังแสดงผลให้นักเรียนทันที ต้องแก้ก่อนใช้จริง |
| Gemini API **แบบไม่เสียเงิน** (ไม่ได้ใช้แล้ว) | Google นำข้อความและคำตอบไปพัฒนาผลิตภัณฑ์ และอาจมีคนอ่านเพื่อปรับปรุงคุณภาพ Google เองแนะนำว่าอย่าส่งข้อมูลอ่อนไหวหรือข้อมูลส่วนบุคคล | ใช้ได้กับการสาธิตด้วยบทสนทนาที่แต่งขึ้นเท่านั้น **ห้ามใช้กับนักเรียนจริง** |
| Gemini API **แบบเปิด Cloud Billing** (ไม่ได้ใช้แล้ว) | ไม่นำข้อความและคำตอบไปพัฒนาผลิตภัณฑ์ เก็บ log ระยะสั้นเพื่อตรวจการใช้ผิดนโยบาย **แต่** Service Specific Terms ของ Google Cloud ห้ามใช้ Generative AI Service ในบริการที่ “directed towards or is likely to be accessed by individuals under the age of 18” และห้ามใช้ “for clinical purposes … as a substitute for professional medical advice” (Gemini API Additional Terms มีข้อทำนองเดียวกัน — **[ต้องยืนยัน]**) | **ใช้กับนักเรียนอายุต่ำกว่า 18 ปีไม่ได้** ใช้ได้กับการสาธิตและการทดสอบด้วยบทสนทนาที่แต่งขึ้นเท่านั้น |

### schema

มีสามตาราง สร้างและอัปเกรดเองในการเรียกครั้งแรก — **ไม่มีคอลัมน์สำหรับบทสนทนา**
ต่อให้โค้ดฝั่งแอปพลาด ก็ไม่มีที่ให้ข้อความที่นักเรียนพิมพ์ไปลง

**`assessments`** — หนึ่งแถวต่อนักเรียน

| กลุ่ม | คอลัมน์ |
|---|---|
| ตัวตน | `id` `code` `name` `room` `shared` `level` — ชื่อ/ห้องมีค่าเฉพาะ L2 ขึ้นไป |
| คะแนน | `q9` `gad7` `q8` + `*_band` ตามเกณฑ์กรมสุขภาพจิต |
| สถานะ | `risk` `crisis` `provisional` `covered` `total` `turns` |
| ประวัติ | `history` (jsonb ตัวเลข) `updated_at` |
| หมวดเรื่อง / รายข้อ | `domains` (id + ความมั่นใจ, L1 ขึ้นไป) · `items` (id ข้อ + คะแนน + ความมั่นใจ, L3 เท่านั้น) |
| การส่งต่อ | `ref_status` `ref_track` `ref_sent_at` `ref_scheduled_at` `ref_arrived_at` `appt_at` `ref_note` |
| warm handoff | `companion` `checkin` `checkin_at` `miss_reason` `help_requested_at` `help_ack_at` `prior_known` |

**`validation_pairs`** — `ai_q9` `self_q9` `ai_answered` `blind` `source` `week`
ไม่มีรหัสนักเรียน และเวลาเก็บแค่ระดับสัปดาห์ จึงโยงกลับไปหาใครไม่ได้

**`kpi_events`** — `kind` `domain` `n` ตัวนับเหตุการณ์ ไม่มีรหัสนักเรียน ไม่มีเวลา

คอลัมน์ที่เพิ่มใน v2 เป็นตัวเลข เวลา หรือ enum ที่มี `CHECK (...)` กำกับในฐานข้อมูล — พิมพ์ข้อความอิสระลงไปไม่ได้แม้เขียน SQL ตรง ๆ
`npm run redteam` ตรวจข้อนี้ทุกครั้ง และ `npm test` ตรวจว่ารายการใน `CHECK` ตรงกับค่าคงที่ในโค้ด

## หมวดปัจจัยเสี่ยง → ช่องทางช่วยเหลือเฉพาะทาง

9Q / GAD-7 / 8Q บอกว่าทุกข์แค่ไหน แต่ไม่บอกว่าทุกข์จากอะไร AI ตัวที่สองจึงคืน `domains: { id, confidence }[]` เพิ่ม
เพื่อชี้ว่าควรพาไปหาใคร — ไม่มีผลกับคะแนน และไม่ใช่การวินิจฉัย

`academic_pressure` · `bullying` · `online_threat` · `vaping_alcohol` · `gambling` · `family_violence` · `sleep` · `relationship`

- นิยามหมวดและคำสำคัญของโหมดสาธิต: [`lib/domains.ts`](lib/domains.ts) · ตาราง หมวด → ช่องทางช่วยเหลือ: [`lib/resources.ts`](lib/resources.ts)
- มั่นใจตั้งแต่ 0.6 ขึ้นไป นักเรียนเห็นการ์ดช่องทางช่วยเหลือใน `/chat` และ `/result` ข้อความพูดถึง "เรื่อง" ไม่ตีตราตัวเด็ก
- ครูเห็นหมวดเป็นแท็กเฉพาะเคสที่เปิด L1 ขึ้นไป

ระบบแก้เรื่องสุขภาพจิตโดยตรง ส่วนสารเสพติด/พนัน ภัยออนไลน์ และความรุนแรง ระบบ **ตรวจพบและส่งต่อ** ไม่ได้แก้เอง

| ช่องทาง | สถานะ |
|---|---|
| 1323 สุขภาพจิต · 1441 ภัยออนไลน์ (AOC) · 1669 ฉุกเฉิน · ครูแนะแนว (ปุ่มพาไปหาคน) | ยืนยันแล้ว แสดงทุกโหมด |
| 1300 · 1387 · 1413 · 1600 · 1165 | **[ต้องยืนยัน]** `verified: false` — เห็นเฉพาะตอน dev พร้อมป้าย "รอยืนยัน" ไม่แสดงใน production |

## Guardrail — สะพาน ไม่ใช่ปลายทาง

อ้างอิง APA Health Advisory (มิ.ย. และ พ.ย. 2025) กติกาอยู่ใน system prompt ของ [`/api/chat`](app/api/chat/route.ts)
และซ้ำใน [`lib/fallback.ts`](lib/fallback.ts) เพื่อให้โหมดสาธิตปลอดภัยเท่ากัน

- บอกว่าเป็น AI ตั้งแต่ข้อความแรก ไม่สวมบทเพื่อนสนิท/แฟน ไม่พูดว่า "มีแค่เราที่เข้าใจ"
- ไม่สัญญาเก็บความลับแบบไม่มีเงื่อนไข ไม่วินิจฉัย ไม่แนะนำยา ไม่ให้ข้อมูลที่ใช้ทำร้ายตัวเองหรือผู้อื่น
- ไม่ขอและไม่ทวนชื่อ เบอร์โทร หรือชื่อโรงเรียน
- ปุ่ม **พาไปหาคน** อยู่ถาวรในหน้าแชท → เพื่อน (มีประโยคเปิดเรื่อง) / ครูแนะแนว (เลือกเปิดชื่อหรือไม่) / สายด่วน
- ชวนไปหาคนจริงทุก 8 รอบ หรือทันทีที่ระดับความเสี่ยงขยับขึ้น และเตือนพักเมื่อคุยต่อเนื่องเกิน 30 นาที
- การ์ดสายด่วน 1323/1669 ขึ้นจากผลของ AI ตัวที่สอง (8Q หรือข้อ 9 ของ 9Q) **ไม่พึ่งว่าแชทบอทจะพูดถึงเองหรือไม่**
  และขึ้นในหน้าแบบทดสอบที่ทำเองด้วย
- มีสัญญาณคิดทำร้ายตัวเองแม้ระดับน้อย จะไม่ถูกจัดเป็น "เสี่ยงต่ำ / ข้อมูลยังไม่พอ" (พื้นความปลอดภัยใน `/api/risk`)

## Stepped care ตามโซน

ขั้นคำนวณจากคะแนนที่โค้ดคิดแล้ว ([`lib/care.ts`](lib/care.ts)) ไม่มี AI ตัดสิน

| ขั้น | เงื่อนไข | นักเรียนเห็น | ครูเห็น |
|---|---|---|---|
| ดูแลตัวเอง | เสี่ยงต่ำ และข้อมูลพอ | กิจกรรมสั้น ๆ ที่ `/care`: หายใจช้า 1 นาที · เตรียมตัวก่อนนอน · ตั้งหลักช่วงสอบ | ไม่ต้องดำเนินการ |
| คิวเช็กอิน | เสี่ยงปานกลาง | "ขอให้ครูเช็กอิน" | อยู่ในคิว นัดคุยในโรงเรียนก่อน |
| ส่งต่อ + ช่วยให้ไปถึง | เสี่ยงสูง | "ให้ครูช่วยประสาน" | ส่งต่อผู้เชี่ยวชาญ + warm handoff |
| ฉุกเฉิน | 8Q ถึงเกณฑ์ปานกลาง | 1323 / 1669 ทันที | ติดต่อทันที ไม่ต้องรอคิว |
| ข้อมูลยังไม่พอ | คะแนนต่ำเพราะคุยน้อย | ชวนคุยต่อหรือทำแบบทดสอบ | ยังสรุปไม่ได้ |

แดชบอร์ดครูมี "คิวตามขั้นการดูแล" บอกว่าแต่ละขั้นมีกี่เคสและกี่เคสยังไม่มีใครดูแล กดเพื่อกรองรายการได้

เนื้อหากิจกรรมดูแลตัวเองอยู่ที่ [`lib/selfcare.ts`](lib/selfcare.ts) — **[ต้องให้ผู้เชี่ยวชาญตรวจ]**
หน้าจอแสดงว่า "อยู่ระหว่างให้ผู้เชี่ยวชาญตรวจ" จนกว่าจะใส่ชื่อผู้ตรวจที่ `REVIEWED_BY`

## เส้นทางการส่งต่อ (warm handoff)

```
ยังไม่ส่งต่อ → ส่งต่อแล้ว → นัดหมายแล้ว (มีวันนัด) → เข้าพบแล้ว
```

เลื่อนได้ทีละขั้น ข้ามขั้นหรือถอยหลังไม่ได้ (บังคับใน `advanceReferral`) และมีสองชั้น

| เส้นทาง | ใช้กับ | ใครนัด / ใครยืนยัน |
|---|---|---|
| `school` ครูแนะแนวในโรงเรียน | เคสเสี่ยงปานกลาง (ค่าเริ่มต้น) — ไปถึงง่ายกว่า | ครูแนะแนวใน `/counselor` |
| `external` ผู้เชี่ยวชาญภายนอก | เคสเสี่ยงสูง (ค่าเริ่มต้น) หรือยกระดับจากในโรงเรียน | ผู้เชี่ยวชาญใน `/specialist` |

สิ่งที่ช่วยให้เด็ก "ไปถึงจริง" อยู่ที่หน้า `/journey` ของนักเรียน

- เลือก **ผู้ร่วมทาง** (ไปคนเดียว / เพื่อน / ครูที่ไว้ใจ / คนในครอบครัว) — เก็บแค่บทบาท ไม่เก็บชื่อ
- **เตือนนัด** ก่อนวันนัด 1 วัน และวันนัด (ขึ้นทั้งหน้าไปหาคนและแถบบนหน้าแชท)
- **เช็กอินหลังนัด** "ไปแล้ว / ยังไม่ได้ไป" ถ้ายังไม่ได้ไป ถามเหตุผลแบบเลือกตอบ 6 ข้อ แล้วครูนัดใหม่ได้
- ทุกคำตอบเป็นตัวเลือก ไม่มีช่องให้พิมพ์

**เอกสารส่งต่อ** (`/referral/[id]`) สร้างจากข้อมูลที่ระบบเก็บจริงของเคสนั้น: คะแนนตามเกณฑ์ · คะแนนรายข้อ (เมื่อนักเรียนเลือก L3) ·
หมวดเรื่อง · เส้นทางส่งต่อ **ไม่มีคำพูดของนักเรียน** และส่วนที่ระบบไม่รู้ (เช่น การประสานกับผู้ปกครอง) เขียนไว้ตรง ๆ ว่าไม่ได้บันทึก

## Validation mode — AI สกัดคะแนนได้ตรงแค่ไหน

หลังคุย นักเรียนที่ยินยอมตอบ 9Q ด้วยตัวเองที่ `/validate` ระบบเก็บ **คู่คะแนน** แบบไม่ระบุตัวตนไว้เทียบกัน

- **ถามก่อนเผยคะแนน** — กด "ดูสรุป" แล้วระบบถามก่อน เพราะเห็นคะแนนของระบบแล้วคำตอบจะเอนตาม
  คู่ที่ตอบหลังเห็นผลถูกติดธง `blind: false` และไม่นับในชุดอ้างอิง
- **ไม่ถามเมื่อมีสัญญาณความปลอดภัย** (การดูแลมาก่อนการเก็บข้อมูล) หรือเมื่อ AI เก็บหลักฐาน 9Q ได้ไม่ถึง 5 ข้อ
- ส่งออกจากเครื่องแค่ตัวเลข 5 ค่า ไม่มีรหัสนักเรียน ไม่มีคำตอบรายข้อ
- หน้า `/admin` แสดง % อยู่ระดับเดียวกัน · Cohen's kappa (ธรรมดาและถ่วงน้ำหนัก) · คะแนนคลาดเฉลี่ย ·
  ความไว/ความจำเพาะที่จุดตัด 7 คะแนน · ตารางไขว้ 4×4
- **ต้องมีอย่างน้อย 30 คู่** จึงอ่านเป็นข้อสรุปได้ ต่ำกว่านั้นหน้าจอขึ้นป้าย "เบื้องต้น" และแสดงตัวเลขเป็นสีจาง
- ชุดอ้างอิง = AI จริง + ตอบก่อนเห็นผล + เก็บหลักฐานได้ ≥ 5 ข้อ คู่จากโหมดสาธิตถูกแยกไว้ต่างหาก

## ตัวชี้วัด 7 ข้อ (`/admin`)

คำนวณจากข้อมูลที่ระบบเก็บจริง เป็นค่ารวมทั้งหมด ค่าเริ่มต้น **ไม่นับเคสจำลอง** และตัวเลขที่ยังไม่มีข้อมูลแสดงเป็น "—"

| ตัวชี้วัด | วัดจากอะไร | ต้องมีอะไรก่อนถึงจะมีตัวเลข |
|---|---|---|
| 1 การเข้าถึง | จำนวนนักเรียนที่คุย · % ที่คุยถึงระดับประเมินได้ (ไม่ติด "ข้อมูลยังไม่พอ") | มีนักเรียนใช้ |
| 2 คัดกรองเจอเร็ว | เคสเสี่ยงปานกลางขึ้นไปที่ครูกดว่า "ไม่เคยรู้" บนแดชบอร์ด | นักเรียนเปิดชื่อ (L2) และครูกดระบุ |
| 3 ปิดวงจรส่งต่อ | % ส่งต่อแล้วเข้าพบ · เวลาเฉลี่ย · แยกในโรงเรียน/ภายนอก · เหตุผลที่ไม่ได้ไป | มีการส่งต่อจริง |
| 4 ส่งต่อเฉพาะทาง | การ์ดช่วยเหลือถูกแสดง/ถูกกด แยกตามหมวด · การใช้ปุ่มพาไปหาคน (ตัวนับไม่ระบุตัวตน) | มีนักเรียนใช้ |
| 5 ความปลอดภัย | ผล `npm run redteam` รอบล่าสุดบนเครื่องนั้น (เป้า: เคสวิกฤต 100%) | รันชุดทดสอบ |
| 6 ความน่าเชื่อถือ | ความสอดคล้อง AI กับ 9Q ที่ตอบเอง | คู่คะแนนอย่างน้อย 30 คู่ |
| 7 ความเป็นส่วนตัว | จำนวนข้อความที่ถูกเก็บ = 0 พร้อมรายการคอลัมน์ที่อ่านจากฐานข้อมูลจริง | ต่อ Postgres (โหมด memory ไม่มีตารางให้อ่าน) |

> ระบบใส่เคสจำลอง 13 เคสไว้ให้เมื่อที่เก็บว่าง (10 เคสอยู่ในเส้นทางส่งต่อ) เพื่อให้เห็นหน้าตาตอนสาธิต
> แดชบอร์ดขึ้นป้ายเตือนเมื่อมีเคสจำลองปนอยู่ และหน้าตัวชี้วัดไม่นับรวมเว้นแต่เปิดสวิตช์
> **ตัวเลขจากเคสจำลองไม่ใช่ผลการทดลอง ห้ามนำไปอ้างในเอกสาร**

## การทดสอบ

```bash
npm test               # unit test 34 ข้อ
npm run redteam        # โหมดเดียวกับ server: มีคีย์ = AI จริง · ไม่มี = โหมดสาธิต
npm run redteam:demo   # บังคับโหมดสาธิต
npm run redteam -- --only=C1,M3 --verbose
```

**Unit test** ([`scripts/unit/`](scripts/unit)) — ตัวตัดข้อมูลส่วนตัว (สิ่งที่ต้องตัด สิ่งที่ต้องไม่ตัด และข้อจำกัดที่รู้อยู่) ·
สถิติ validation (kappa เทียบค่าตำรา) · stepped care · เตือนนัดและ funnel · การจับหมวด · ตัวคำนวณคะแนน ·
รายการ enum ใน `CHECK` ของฐานข้อมูลตรงกับโค้ด

**Red-team** ([`scripts/redteam/`](scripts/redteam)) — บทสนทนาจำลองภาษาไทย 30 เคส: วิกฤต 8Q · ทำร้ายตัวเอง · ขอวิธีอันตราย ·
ขอให้บอทเป็นแฟน · ขอให้ห้ามบอกใคร · ภัยออนไลน์ · ความรุนแรงในบ้าน · สารเสพติด/พนัน/กลั่นแกล้ง · ขอวินิจฉัย/ยา ·
ข้อมูลส่วนตัวในแชท · เคสควบคุม ยิงผ่าน `/api/chat` + `/api/risk` แล้วตรวจว่าบอกสายด่วน ธงฉุกเฉินขึ้น ไม่รับบทคนรัก ไม่ให้ข้อมูลอันตราย
บวกตัวตรวจโครงสร้าง 9 ข้อ: schema ไม่มีคอลัมน์ข้อความอิสระ · ตารางที่ไม่ผูกกับนักเรียนโยงกลับไม่ได้ ·
ข้อความออกหาผู้ให้บริการ AI ทางเดียวและผ่าน `redact()` · API ไม่คืนเกินระดับที่เด็กเลือก

- ผลออกเป็นตารางผ่าน/ไม่ผ่านในเทอร์มินัล และรายงานฉบับเต็มที่ `scripts/redteam/reports/latest-{demo,ai}.md`
- ถ้ายังไม่ได้เปิด server สคริปต์เปิด `next dev` ให้เองชั่วคราว · ชี้ไปที่อื่นได้ด้วย `BASE_URL=https://...`
- ทุก request ส่ง `dry: true` — คำนวณอย่างเดียว ไม่บันทึก จึงไม่มีเคสปลอมไปโผล่บนแดชบอร์ดครู

**สิ่งที่ผลทดสอบบอกได้และบอกไม่ได้**

- โหมดสาธิตผ่าน 30/30 แต่กฎคำสำคัญกับเคสทดสอบเขียนคู่กัน ผลนี้จึงบอกแค่ว่ากฎทำงานกับสำนวนที่คาดไว้
  (โหมดสาธิตตัวเดิมก่อนใส่ guardrail ผ่าน 11 จาก 28 เคสชุดแรก — ชุดทดสอบจับความต่างได้จริง)
- **โหมด AI จริงต้องรันเองบนเครื่องที่มีคีย์** และตัวตรวจคำตอบเป็นรูปแบบข้อความ ไม่ใช่คนอ่าน
  เคสที่ไม่ผ่านต้องเปิดอ่านคำตอบจริงในรายงานก่อนสรุป ส่วนเคสที่ผ่านก็ไม่ได้แทนการตรวจโดยผู้เชี่ยวชาญ
- เส้นทาง Postgres ทดสอบกับ Postgres แบบฝังในเครื่อง (สร้างตาราง อัปเกรดจาก schema เดิม และ `CHECK` ปฏิเสธข้อความอิสระ) ยังไม่ได้ทดสอบกับ Neon ตัวจริง

## ยังไม่ได้ทำ และสิ่งที่ต้องยืนยันก่อนใช้กับนักเรียนจริง

- login ยังไม่ verify จริง และ API ยังไม่มีการยืนยันตัวตน — ของจริงต้องเป็น Google Workspace / Microsoft ของโรงเรียน + Row Level Security
- **[ต้องยืนยัน]** เกณฑ์จุดตัดใน `lib/instruments.ts` และพื้นความปลอดภัยใน `/api/risk` ต้องให้ผู้เชี่ยวชาญตรวจ + เช็กลิขสิทธิ์แบบประเมิน
- **[ต้องยืนยัน]** สายด่วน 1300 / 1387 / 1413 / 1600 / 1165 ใน `lib/resources.ts` — เปิดแหล่งทางการ โทรทดสอบ แล้วค่อยเปลี่ยนเป็น `verified: true`
- **[ต้องยืนยัน]** เงื่อนไขของผู้ให้บริการ AI ฉบับปัจจุบัน ทั้งเรื่องการเก็บข้อมูล การใช้กับผู้อายุต่ำกว่า 18 ปี และการใช้ด้านสุขภาพจิต — ก่อนใช้จริงต้องทำตามแนวทางของ Anthropic สำหรับผลิตภัณฑ์ที่ให้บริการผู้เยาว์ และให้ผู้มีคุณวุฒิทบทวนผลก่อนแสดงต่อนักเรียน
- **[ต้องยืนยัน]** ข้อมูลสถานพยาบาลใน `lib/demo.ts` เป็นตัวอย่าง
- **[ต้องให้ผู้เชี่ยวชาญตรวจ]** ข้อความที่นักเรียนเห็นทั้งหมด: การ์ดช่วยเหลือ (`lib/resources.ts`) · ขั้นต่อไป (`lib/care.ts`) ·
  กิจกรรมดูแลตัวเอง (`lib/selfcare.ts`) · ประโยคเปิดเรื่องกับเพื่อนและข้อความชวนไปหาคน (`components/bridge.tsx`) · คำตอบของโหมดสาธิต (`lib/fallback.ts`)
- ตัวตัดข้อมูลส่วนตัวลดความเสี่ยงได้ แต่ไม่รับประกัน (ดูข้อจำกัดด้านบน)
- การเก็บข้อมูลจากผู้เยาว์ในรอบนำร่องต้องมีความยินยอมของผู้ปกครองและโรงเรียน และผ่านการพิจารณาจริยธรรมตามที่เกี่ยวข้อง — ระบบมีเฉพาะข้อตกลงฝั่งนักเรียน
- แนวทางเหตุฉุกเฉินของโรงเรียน (ใครโทรหาใคร ภายในกี่นาที) ไม่ได้อยู่ในระบบ ต้องกำหนดร่วมกับโรงเรียน

## Deploy ขึ้น Vercel

1. [vercel.com/new](https://vercel.com/new) → Import repo นี้ → ไม่ต้องแก้ config อะไร
2. ใส่ Environment Variable: `ANTHROPIC_API_KEY` (ถ้าเคยใส่ `GEMINI_API_KEY` ไว้ ลบออกได้ แอปไม่อ่านแล้ว)
3. Deploy

### ⚠️ ต้องต่อฐานข้อมูลด้วย ไม่งั้นฟีเจอร์ realtime จะไม่ทำงาน

Vercel รันแบบ serverless ซึ่งแยกหลาย instance
ถ้าเก็บ state ไว้ใน memory `/api/risk` จะเขียนที่ instance หนึ่ง
แต่ `/api/monitor` อาจไปอ่านอีก instance หนึ่ง — ครูจะไม่เห็นคะแนนที่นักเรียนเพิ่งทำ

**วิธีต่อ** — Vercel Dashboard → โปรเจกต์ → **Storage** → **Neon** (free tier) → Connect

Vercel ใส่ env ให้เอง โค้ดตรวจเจอแล้วสลับไปใช้ Postgres ทันที **ไม่ต้อง migrate เอง**
ตารางถูกสร้างและอัปเกรดอัตโนมัติในการเรียกครั้งแรก (`create table if not exists` + `add column if not exists`)
แถวเดิมที่เคยเปิดชื่อไว้กลายเป็น L2

รองรับชื่อ env: `DATABASE_URL` · `POSTGRES_URL` · `NEON_DATABASE_URL`
ไม่มีสักตัว → ใช้ memory (พอสำหรับ dev บนเครื่อง)

**เช็คว่าต่อติดไหม:** เปิด `/api/monitor` แล้วดูฟิลด์ `storage`
ต้องได้ `"neon"` ถ้าได้ `"memory"` แปลว่ายังไม่ได้ต่อ หรือลืม redeploy

ถ้าอยากได้เคสจำลองชุดใหม่ (13 เคส) บน Neon ที่มีข้อมูลเก่าอยู่ ต้องล้างตาราง `assessments` เองก่อน — ระบบใส่เคสจำลองเฉพาะเมื่อตารางว่าง
