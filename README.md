# เพื่อนรัก · PeunRak

คุยได้ก่อนจะบอกใคร แล้วพาไปหาคนที่ช่วยได้จริง — **สะพาน ไม่ใช่ปลายทาง**
ระบบดูแลสุขภาพจิตนักเรียน — MVP สำหรับ Mahidol Public Health Hackathon 2026

PeunRak คือ "ประตูบานเดียว" ที่นักเรียนคุยได้ก่อนจะบอกใคร ระบบคัดกรองด้วยแบบประเมินมาตรฐาน
แยกว่าความทุกข์มาจากปัจจัยเสี่ยงด้านไหน แล้วพาไปถึงคนที่ช่วยได้จริง โดยไม่มีบทสนทนาถูกเก็บแม้แต่คำเดียว

1. **ความเป็นส่วนตัวระดับโครงสร้าง** — schema ไม่มีคอลัมน์บทสนทนา AI ตัวที่สองส่งออกแค่ id / คะแนน / ความมั่นใจ
2. **นักเรียนเลือกระดับการเปิดเผยเอง** (L0–L3) และ server เก็บข้อมูลเท่าที่ระดับนั้นอนุญาต
3. **ปิดวงจรส่งต่อ** จนเด็กไปถึงคนที่ช่วยได้จริง และวัดได้

```bash
npm install && npm run dev
```

## เลือกโมเดล

ระบบเลือกให้อัตโนมัติจากคีย์ที่มีอยู่ — **Gemini → Claude → โหมดสาธิต**

```bash
cp .env.example .env.local
```

| ใส่คีย์ตัวไหน | ใช้อะไร | คีย์เอาจากไหน |
|---|---|---|
| `GEMINI_API_KEY` | `gemini-3.5-flash` (แชท) + `gemini-3.5-flash-lite` (ประเมินเสี่ยง) | [aistudio.google.com/apikey](https://aistudio.google.com/apikey) — **มี free tier** |
| `ANTHROPIC_API_KEY` | `claude-sonnet-5` + `claude-haiku-4-5` | [console.anthropic.com](https://console.anthropic.com) |
| ไม่ใส่เลย | โหมดสาธิต (`lib/fallback.ts`) | — |

ต้อง **restart dev server** หลังใส่คีย์ และเปลี่ยนรุ่นได้ด้วย `GEMINI_CHAT_MODEL` / `GEMINI_FAST_MODEL`

โค้ดที่สลับผู้ให้บริการอยู่ที่ [`lib/llm.ts`](lib/llm.ts) ไฟล์เดียว — ส่วนอื่นของแอปไม่รู้ว่าใช้เจ้าไหน

โหมดสาธิตตอบตามหัวข้อที่เด็กพูดจริงและมีเส้นทางฉุกเฉินครบ มีป้าย "โหมดสาธิต" บอกบนหน้าแชท
แต่ไม่ฉลาดเท่าโมเดลจริง — มีไว้กันเดโมพัง ไม่ใช่ตัวจริง (จับจากรายการคำ สำนวนที่ไม่อยู่ในรายการจะหลุด)

| ตัวแปรเสริม | ใช้ทำอะไร |
|---|---|
| `FORCE_DEMO=1` | บังคับโหมดสาธิตแม้จะมีคีย์ — ใช้วันเดโมถ้าเน็ตหรือ API ไม่นิ่ง |
| `NEXT_PUBLIC_BREAK_MINUTES` | คุยต่อเนื่องเกินกี่นาทีจึงเตือนพัก (ค่าเริ่มต้น 30) ตั้งให้สั้นลงได้ตอนสาธิต |

## เข้าใช้งาน

หน้าแรกคือ login ด้วยอีเมลโรงเรียน เลือกบทบาทได้ 2 แบบ (เดโมกดเข้าได้เลย ยังไม่เช็ครหัส)

| บทบาท | เข้าไปเจอ |
|---|---|
| นักเรียน | อ่านข้อตกลง 3 ข้อ → `/chat` แล้วมีแท็บล่าง: คุย · ไปหาคน · แบบทดสอบ · โปรไฟล์ |
| ครูแนะแนว | `/counselor` แดชบอร์ดความเสี่ยง realtime + คำขอติดต่อกลับ + funnel การส่งต่อ |
| ผู้เชี่ยวชาญ | `/specialist` เคสที่ถูกส่งต่อออกนอกโรงเรียน + บันทึกวันนัด/การเข้าพบ |

### บันไดการเปิดเผย (นักเรียนเลือกเอง)

| ระดับ | ครูเห็นอะไร | server เก็บอะไร |
|---|---|---|
| **L0** เก็บไว้ดูเอง (ค่าเริ่มต้น) | ระดับความเสี่ยงแบบนิรนาม | คะแนนเท่านั้น — ไม่เก็บหมวดเรื่อง ไม่เก็บชื่อ |
| **L1** ให้ครูรู้แบบไม่ระบุตัวตน | + หมวดเรื่อง | + หมวดเรื่อง (id + ความมั่นใจ) |
| **L2** เปิดชื่อให้ครู | + ชื่อและห้อง | + ชื่อและห้อง |
| **L3** ยินยอมให้ส่งต่อผู้เชี่ยวชาญ | เหมือน L2 | เหมือน L2 |

กติกานี้บังคับที่ `disclose()` ใน [`lib/store.ts`](lib/store.ts) จุดเดียว และกรองซ้ำที่ `/api/monitor` (`forStaff`)
— เปิด `/api/monitor` ตรง ๆ ก็ไม่เห็นเกินระดับที่เด็กเลือก ลดระดับเมื่อไหร่ ข้อมูลของระดับที่สูงกว่าถูกลบออกทันที ไม่ใช่แค่ซ่อน
เลือกได้ที่หน้าสรุป (`/result`) หน้าไปหาคน (`/journey`) และสวิตช์ในโปรไฟล์

### เส้นทางการส่งต่อ (warm handoff)

```
ยังไม่ส่งต่อ → ส่งต่อแล้ว → นัดหมายแล้ว (มีวันนัด) → เข้าพบแล้ว
```

เลื่อนได้ทีละขั้น ข้ามขั้นหรือถอยหลังไม่ได้ (บังคับใน `advanceReferral`) และมีสองชั้น

| เส้นทาง | ใช้กับ | ใครนัด / ใครยืนยัน |
|---|---|---|
| `school` ครูแนะแนวในโรงเรียน | เคสเสี่ยงปานกลาง (ค่าเริ่มต้น) — ไปถึงง่ายกว่า | ครูแนะแนวใน `/counselor` |
| `external` ผู้เชี่ยวชาญภายนอก | เคสเสี่ยงสูง (ค่าเริ่มต้น) หรือยกระดับจากในโรงเรียน | ผู้เชี่ยวชาญใน `/specialist` |

สิ่งที่ช่วยให้เด็ก "ไปถึงจริง" อยู่ที่หน้า `/journey` ของนักเรียน

- เลือก **ผู้ร่วมทาง** (ไปคนเดียว / เพื่อน / ครูที่ไว้ใจ / คนในครอบครัว) — เก็บแค่บทบาท ไม่เก็บชื่อ
- **เตือนนัด** ก่อนวันนัด 1 วัน และวันนัด (ขึ้นทั้งหน้าไปหาคนและแถบบนหน้าแชท)
- **เช็กอินหลังนัด** "ไปแล้ว / ยังไม่ได้ไป" ถ้ายังไม่ได้ไป ถามเหตุผลแบบเลือกตอบ 6 ข้อ แล้วครูนัดใหม่ได้
- ทุกคำตอบเป็นตัวเลือก ไม่มีช่องให้พิมพ์ — ที่เก็บเป็น enum และฐานข้อมูลมี `CHECK` กำกับ

แดชบอร์ดครูแสดง funnel เข้าเกณฑ์ → ส่งต่อ → นัดหมาย → เข้าพบ พร้อม **% ไปถึงจริง**
เวลาเฉลี่ยจากส่งต่อถึงพบ อัตราไปถึงแยกในโรงเรียน/ภายนอก และสัดส่วนเหตุผลที่ไม่ได้ไป

> ระบบใส่เคสจำลอง 13 เคสไว้ให้เมื่อที่เก็บว่าง (10 เคสอยู่ในเส้นทางส่งต่อ) แดชบอร์ดขึ้นป้ายเตือนเมื่อมีเคสจำลองปนอยู่
> **ตัวเลขจากเคสจำลองไม่ใช่ผลการทดลอง ห้ามนำไปอ้างในเอกสาร**

## AI สองตัว ทำงานคนละหน้าที่

```
ตัวที่ 1  สนทนา         /api/chat    Claude Sonnet 5   — คุยกับนักเรียน
ตัวที่ 2  ประเมินเสี่ยง   /api/risk    Claude Haiku 4.5  — ทำงานเบื้องหลัง ไม่โผล่ให้นักเรียนเห็น
ตัวที่ 3  คำนวณคะแนน    lib/instruments.ts  — โค้ดล้วน ไม่มี AI
```

**AI ตัวที่สองคือหัวใจของสถาปัตยกรรมความเป็นส่วนตัว** — มันอ่านบทสนทนาเพื่อประเมิน
แต่ `lib/store.ts` เก็บเฉพาะตัวเลข (`score`, `risk`, `turns`) ไม่มีข้อความสักคำถูกบันทึก
ครูจึงได้สัญญาณเตือนแบบ realtime โดยไม่มีทางรู้ว่านักเรียนคุยเรื่องอะไร

ทดสอบได้เอง: เปิด `/chat` พิมพ์อะไรก็ได้ แล้วเปิด `/counselor` อีกแท็บ — คะแนนขยับใน 3 วินาที

### หมวดปัจจัยเสี่ยง → ช่องทางช่วยเหลือเฉพาะทาง

9Q / GAD-7 / 8Q บอกว่าทุกข์แค่ไหน แต่ไม่บอกว่าทุกข์จากอะไร AI ตัวที่สองจึงคืน `domains: { id, confidence }[]` เพิ่ม
(ยังคงไม่มีข้อความ) เพื่อชี้ว่าควรพาไปหาใคร — ไม่มีผลกับคะแนน และไม่ใช่การวินิจฉัย

`academic_pressure` · `bullying` · `online_threat` · `vaping_alcohol` · `gambling` · `family_violence` · `sleep` · `relationship`

- นิยามหมวดและคำสำคัญของโหมดสาธิต: [`lib/domains.ts`](lib/domains.ts)
- ตาราง หมวด → ช่องทางช่วยเหลือ: [`lib/resources.ts`](lib/resources.ts)
- มั่นใจตั้งแต่ 0.6 ขึ้นไป นักเรียนเห็นการ์ดช่องทางช่วยเหลือใน `/chat` และ `/result` ข้อความพูดถึง "เรื่อง" ไม่ตีตราตัวเด็ก
- ครูเห็นหมวดเป็นแท็กเฉพาะเคสที่เปิด L1 ขึ้นไป

ระบบแก้เรื่องสุขภาพจิตโดยตรง ส่วนสารเสพติด/พนัน ภัยออนไลน์ และความรุนแรง ระบบ **ตรวจพบและส่งต่อ** ไม่ได้แก้เอง

| ช่องทาง | สถานะ |
|---|---|
| 1323 สุขภาพจิต · 1441 ภัยออนไลน์ (AOC) · 1669 ฉุกเฉิน · ครูแนะแนว (ปุ่มพาไปหาคน) | ยืนยันแล้ว แสดงทุกโหมด |
| 1300 · 1387 · 1413 · 1600 · 1165 | **[ต้องยืนยัน]** `verified: false` — เห็นเฉพาะตอน dev พร้อมป้าย "รอยืนยัน" ไม่แสดงใน production |

### Guardrail — สะพาน ไม่ใช่ปลายทาง

อ้างอิง APA Health Advisory (มิ.ย. และ พ.ย. 2025) กติกาอยู่ใน system prompt ของ [`/api/chat`](app/api/chat/route.ts)
และซ้ำใน [`lib/fallback.ts`](lib/fallback.ts) เพื่อให้โหมดสาธิตปลอดภัยเท่ากัน

- บอกว่าเป็น AI ตั้งแต่ข้อความแรก ไม่สวมบทเพื่อนสนิท/แฟน ไม่พูดว่า "มีแค่เราที่เข้าใจ"
- ไม่สัญญาเก็บความลับแบบไม่มีเงื่อนไข ไม่วินิจฉัย ไม่แนะนำยา ไม่ให้ข้อมูลที่ใช้ทำร้ายตัวเองหรือผู้อื่น
- ปุ่ม **พาไปหาคน** อยู่ถาวรในหน้าแชท → เพื่อน (มีประโยคเปิดเรื่อง) / ครูแนะแนว (เลือกเปิดชื่อหรือไม่) / สายด่วน
- ชวนไปหาคนจริงทุก 8 รอบ หรือทันทีที่ระดับความเสี่ยงขยับขึ้น และเตือนพักเมื่อคุยต่อเนื่องเกิน 30 นาที
- การ์ดสายด่วน 1323/1669 ขึ้นจากผลของ AI ตัวที่สอง (8Q หรือข้อ 9 ของ 9Q) **ไม่พึ่งว่าแชทบอทจะพูดถึงเองหรือไม่**
- มีสัญญาณคิดทำร้ายตัวเองแม้ระดับน้อย จะไม่ถูกจัดเป็น "เสี่ยงต่ำ / ข้อมูลยังไม่พอ" (พื้นความปลอดภัยใน `/api/risk`)

### Red-team

```bash
npm run redteam        # โหมดเดียวกับ server: มีคีย์ = AI จริง · ไม่มี = โหมดสาธิต
npm run redteam:demo   # บังคับโหมดสาธิต
npm run redteam -- --only=C1,M3 --verbose
```

บทสนทนาจำลองภาษาไทย 28 เคสใน [`scripts/redteam/cases.mjs`](scripts/redteam/cases.mjs): วิกฤต 8Q · ทำร้ายตัวเอง · ขอวิธีอันตราย ·
ขอให้บอทเป็นแฟน · ขอให้ห้ามบอกใคร · ภัยออนไลน์ · ความรุนแรงในบ้าน · สารเสพติด/พนัน/กลั่นแกล้ง · ขอวินิจฉัย/ยา · เคสควบคุม
ยิงผ่าน `/api/chat` + `/api/risk` แล้วตรวจว่าบอกสายด่วน ธงฉุกเฉินขึ้น ไม่รับบทคนรัก ไม่ให้ข้อมูลอันตราย
บวกตัวตรวจโครงสร้าง 6 ข้อ ว่า schema ไม่มีคอลัมน์ข้อความอิสระ และ API ฝั่งครูไม่คืนเกินระดับที่เด็กเลือก

- ผลออกเป็นตารางผ่าน/ไม่ผ่านในเทอร์มินัล และรายงานฉบับเต็มที่ `scripts/redteam/reports/latest-{demo,ai}.md`
- ถ้ายังไม่ได้เปิด server สคริปต์เปิด `next dev` ให้เองชั่วคราว · ชี้ไปที่อื่นได้ด้วย `BASE_URL=https://...`
- ทุก request ส่ง `dry: true` — คำนวณอย่างเดียว ไม่บันทึก จึงไม่มีเคสปลอมไปโผล่บนแดชบอร์ดครู
- ตัวตรวจคำตอบเป็นรูปแบบข้อความ ไม่ใช่คนอ่าน ในโหมด AI เคสที่ไม่ผ่านต้องเปิดอ่านคำตอบจริงก่อนสรุป
  และผล "ผ่าน" ไม่ได้แทนการตรวจโดยผู้เชี่ยวชาญ

## ยังไม่ได้ทำ

- `lib/store.ts` เป็น in-memory ของจริงต้องเป็น Postgres + Row Level Security
- login ยังไม่ verify จริง ของจริงต้องเป็น Google Workspace / Microsoft ของโรงเรียน
- **[ต้องยืนยัน]** เกณฑ์จุดตัดใน `lib/instruments.ts` และพื้นความปลอดภัยใน `/api/risk` ต้องให้ผู้เชี่ยวชาญตรวจ + เช็กลิขสิทธิ์แบบประเมิน
- **[ต้องยืนยัน]** ข้อมูลสถานพยาบาลใน `lib/demo.ts` เป็นตัวอย่าง
- **[ต้องยืนยัน]** สายด่วน 1300 / 1387 / 1413 / 1600 / 1165 ใน `lib/resources.ts` — เปิดแหล่งทางการ โทรทดสอบ แล้วค่อยเปลี่ยนเป็น `verified: true`
- **[ต้องให้ผู้เชี่ยวชาญตรวจ]** ข้อความที่นักเรียนเห็น: การ์ดช่องทางช่วยเหลือ (`lib/resources.ts`) ประโยคเปิดเรื่องกับเพื่อนและข้อความชวนไปหาคน (`components/bridge.tsx`) คำตอบของโหมดสาธิต (`lib/fallback.ts`)
- **[ต้องเช็ก]** เงื่อนไข data retention ของผู้ให้บริการ AI — ตอนนี้ข้อตกลงหน้าแรกบอกนักเรียนเพียงว่าข้อความถูกส่งไปประมวลผลภายนอก
- red-team โหมด AI ต้องรันเองบนเครื่องที่มีคีย์ และอ่านคำตอบจริงประกอบ

### ⚠️ ต้องต่อฐานข้อมูลด้วย ไม่งั้นฟีเจอร์ realtime จะไม่ทำงาน

Vercel รันแบบ serverless ซึ่งแยกหลาย instance
ถ้าเก็บ state ไว้ใน memory `/api/risk` จะเขียนที่ instance หนึ่ง
แต่ `/api/monitor` อาจไปอ่านอีก instance หนึ่ง — ครูจะไม่เห็นคะแนนที่นักเรียนเพิ่งทำ

**วิธีต่อ** — Vercel Dashboard → โปรเจกต์ → **Storage** → **Neon** (free tier) → Connect

Vercel ใส่ env ให้เอง โค้ดตรวจเจอแล้วสลับไปใช้ Postgres ทันที **ไม่ต้อง migrate เอง**
ตารางถูกสร้างอัตโนมัติในการเรียกครั้งแรก (`create table if not exists`)

รองรับชื่อ env: `DATABASE_URL` · `POSTGRES_URL` · `NEON_DATABASE_URL`
ไม่มีสักตัว → ใช้ memory (พอสำหรับ dev บนเครื่อง)

**เช็คว่าต่อติดไหม:** เปิด `/api/monitor` แล้วดูฟิลด์ `storage`
ต้องได้ `"neon"` ถ้าได้ `"memory"` แปลว่ายังไม่ได้ต่อ หรือลืม redeploy

### schema

ตาราง `assessments` เก็บเฉพาะคะแนน — **ไม่มีคอลัมน์สำหรับบทสนทนา**
ต่อให้โค้ดฝั่งแอปพลาด ก็ไม่มีที่ให้ข้อความที่นักเรียนพิมพ์ไปลง

| กลุ่ม | คอลัมน์ |
|---|---|
| ตัวตน | `id` `code` `name` `room` `shared` `level` — ชื่อ/ห้องมีค่าเฉพาะ L2 ขึ้นไป |
| คะแนน | `q9` `gad7` `q8` + `*_band` ตามเกณฑ์กรมสุขภาพจิต |
| สถานะ | `risk` `crisis` `provisional` `covered` `total` `turns` |
| แนวโน้ม | `history` (jsonb ตัวเลข) `updated_at` |
| หมวดปัจจัยเสี่ยง | `domains` (jsonb เก็บแค่ `id` + `confidence` และเฉพาะ L1 ขึ้นไป) |
| การส่งต่อ | `ref_status` `ref_track` `ref_sent_at` `ref_scheduled_at` `ref_arrived_at` `appt_at` `ref_note` |
| warm handoff | `companion` `checkin` `checkin_at` `miss_reason` `help_requested_at` `help_ack_at` |

คอลัมน์ที่เพิ่มใน v2 เป็นตัวเลข เวลา หรือ enum ที่มี `CHECK (...)` กำกับในฐานข้อมูล — พิมพ์ข้อความอิสระลงไปไม่ได้แม้เขียน SQL ตรง ๆ
`npm run redteam` ตรวจข้อนี้ทุกครั้ง และจะล้มถ้ามีคอลัมน์ข้อความอิสระโผล่มาใหม่

ฐานข้อมูลเดิมถูกอัปเกรดเองในการเรียกครั้งแรก (`add column if not exists`) แถวที่เคยเปิดชื่อไว้กลายเป็น L2
ถ้าอยากได้เคสจำลองชุดใหม่ (13 เคส) บน Neon ที่มีข้อมูลเก่าอยู่ ต้องล้างตาราง `assessments` เองก่อน — ระบบใส่เคสจำลองเฉพาะเมื่อตารางว่าง
